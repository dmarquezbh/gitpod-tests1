Onde os testes Python entrariam no ranking

Projeção dos servidores Python “platform” (uvloop, epoll, Cython) e dos frameworks com HTTP nativo (fastpysgi, socketify) sobre o relatório publicado em dmarquezbh.github.io/gitpod-tests1. Só plaintext e json: as demais categorias ainda não foram implementadas nessas variantes.

Isto é projeção, não medição. Os nossos testes rodaram num i7-1355U (WSL), com o servidor fixado em 2 CPUs. Os números absolutos não se comparam. Calibração: a razão sobrevive à troca de máquina?

Três implementações rodaram na nossa máquina e no host de referência. Se a razão sobre o dotnet-platform fosse idêntica, o fator seria 1,00. Usamos esse intervalo como faixa de incerteza (projeção ÷ maior fator até projeção ÷ menor fator).

Leitura

  • plaintext: o python-platform sairia do 14º lugar (CPython/uvicorn, 2.947 req/s) para algo entre o 3º e o 4º, atrás de dotnet-platform e C++ epoll, disputando com Zero C#.
  • json: a faixa é larga, entre o 3º e o 9º. No cenário central fica logo atrás de dotnet-platform e C++, à frente de Rust.
  • No Xeon (RESULTS.md: Rust axum, .NET Kestrel, .NET Platform, Go net/http e Go fasthttp): 2º em plaintext mesmo no pior caso da faixa, atrás só do .NET Platform; 3º–4º em json, disputando com Go fasthttp. A calibração no Xeon é mais apertada (fator 0,97 a 1,40).
  • Fast path (comparar a requisição com a anterior e pular o parser) vale cerca de 10 pontos de razão em plaintext. As variantes “sem fast path” são a comparação mais justa com as demais implementações e ainda ficam no top 4 em plaintext.
  • Python 3.14 com JIT foi a melhor variante pura (0,91 em plaintext), mas a vantagem sobre o 3.14 sem JIT está dentro do ruído de uma rodada.
  • Frameworks com HTTP nativo (fastpysgi, socketify) ficam bem abaixo das versões “platform” em plaintext e tiveram erros; granian não completou (o processo iniciado não era o dono do socket).
  • Nas categorias com banco (db, queries, fortunes, updates) nada muda: as variantes novas não implementam essas rotas, então o Python continua com o CPython/uvicorn publicado.

O que falta para entrar no relatório de verdade

  • Rodar run-python-platform.sh (e as variantes epoll/Cython) no mesmo host do relatório (i5-3317U ou o Xeon), 3 rodadas, e gerar o data.json com tools/build-data.py.
  • Repetir a rodada results-ab3 (Cython, orjson, fastpysgi, socketify): o dotnet-platform caiu para 28 mil req/s em json numa das rodadas, sinal de interferência na máquina.
  • Corrigir o granian para o pid iniciado segurar o listener.
  • Decidir se o fast path entra como variante rotulada (como o TechEmpower faz com “stripped”) ou fica de fora.
  • Implementar db, queries, fortunes e updates para disputar as outras categorias.
